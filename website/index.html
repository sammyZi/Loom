what's in the window

An IDE, not a chat box

Everything the agent touches is visible in panels you already know how to use.

Chat that edits your repo

The agent reads files, writes files, runs commands, searches the web, then reports what changed. Every tool call is shown; nothing happens off-stage.

Terminal panel

Live streaming output, real stdin, Ctrl+C that works. One tab per background job.

Changes panel

Per-file diffs against git. Review the work, stage what you like, commit from the same view.

Browser panel

An iframe and a URL bar for checking the dev server the agent just started — without leaving the app.

Sessions

Every chat is stored locally in SQLite. Searchable, archivable, yours.

A sandbox, not vibes

Commands run in a Job Object with a restricted token and process/memory caps. Installs and clones still work like a normal shell; the whole tree is killed on timeout or cancel. Scratch space lives outside your project.

control

Permissions per call,
not per tool

Every tool call is matched against ordered rules; the last match wins. Allow git status, ask before anything else, and deny git push outright. A denied tool is dropped from the model's schema — it never calls it and never has to explain why it can't.

Agents are presets over this: Build runs unrestricted, Plan can't edit, and read-only subagents explore without touching a file.

providers & cost

Cheap to run, boring about money

Fourteen providers in the catalog, keys configured in Settings and stored in your user profile. Model lists fetch live where supported.

The system prompt is the cached prefix: measured at 94% reuse on turn two, billed at roughly a tenth. Files already read return one-line pointers until they change, old tool output is pruned before history is summarised, and a round that writes nothing ends the loop instead of burning two more.
